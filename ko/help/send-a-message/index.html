API로 메시지 보내기

한 엔드포인트는 비동기로 수락합니다. 성공 코드는 플랫폼이 메시지를 인수했다는 뜻이지, 단말기가 받았다는 뜻은 아닙니다.

6분 읽기 · 업데이트 2026-10-13

호출

엔드포인트와 헤더는 아래와 같습니다. 모든 요청 및 응답 본문은 UTF-8 JSON입니다.

ItemValue
메서드와 경로POST /open/v1/sms/send
Base URLhttps://api.whaleal.com/open/v1
AuthAuthorization: Bearer sk_… (또는 X-API-Key)
Content-Typeapplication/json

두 번 확인할 값

FieldRequired이것이 중요한 이유
toYesE.164 형식. 옵트아웃 비교는 + 기호와 구분자를 제거한 숫자를 기준으로 하므로, 형식이 일관되지 않으면 STOP이 일치하지 않습니다
contentYes규정 준수를 위해 플랫폼에 저장하지 않습니다. 필요하면 고객사에서 직접 보관하세요
fromNo생략하면 플랫폼이 연결에서 발신자를 선택합니다
messageTypeNoMARKETING / INFORMATIONAL / TRANSACTIONAL. 생략하면 가장 엄격한 MARKETING으로 처리됩니다
templateIdNo템플릿 단위로 청구하거나 승인하는 공급자에만 해당합니다. 고객사 공급자 계정에서 만든 템플릿 ID를 전달하세요
Note. 플랫폼은 전달받은 내용을 그대로 보냅니다. 템플릿 변수를 대신 렌더링하지 않으며, 템플릿 정의는 여기가 아니라 고객사 공급자 계정에 있습니다.

기본값이 아니라 TRANSACTIONAL로 시작하세요

messageType은 차단 장치의 유일한 입력입니다. 플랫폼은 메시지 본문을 읽지 않습니다. 따라서 홍보 문구가 우연히 섞인 알림은 TRANSACTIONAL로 선언해 통과하는데, 미국 TCPA 같은 규정에서는 여전히 법적으로 마케팅일 수 있습니다. 유형을 정직하게 선언하는 것은 호출자의 책임입니다.

알 수 없는 값은 조용히 낮은 수준으로 처리하지 않고 HTTP 400과 코드 40000으로 거부됩니다. 의도된 설계입니다. 오타는 연동 오류로 드러나야지, 인증번호가 조용히 오지 않는 상황으로 남겨두지 않습니다.

Scope. 차단은 홍보성 트래픽에만 적용되고, 옵트아웃 처리는 여기서 SMS 개념입니다. 이메일과 WhatsApp도 같은 방식으로 연결되지만, 현재 이 차단 장치는 없습니다.

돌아오는 것은

응답에는 수신자가 다시 표시되고, 실제로 메시지를 전달한 공급자가 명시되며, 대조 시 필요한 필드가 포함됩니다.

FieldMeaning
messageId플랫폼 메시지 ID. 상태 조회와 콜백 중복 제거에 사용하세요
status메시지가 현재 어느 단계에 있는지 — "각 메시지 상태의 의미" 참고
providerMessageId공급자측 ID. null이면 공급자가 접수하지 않았다는 뜻이며, 따라서 과금도 되지 않습니다
rawStatus정규화 전 공급자 원문으로, 진단용으로만 의미가 있습니다
encodingGSM7 / UCS2 / UTF8 / GBK — 실제 사용된 인코딩
segments이 메시지의 과금 세그먼트

중복 발송 대부분을 막는 한 가지 규칙

멱등키가 없습니다. 같은 요청을 두 번 보내면 메시지가 두 번 발송되고 두 번 과금됩니다. 접수가 비동기이므로 네트워크 시간 초과는 발송이 이미 이루어졌을 수 있다는 뜻입니다. 시간 초과를 실패가 아니라 미확인으로 처리하세요.

  • messageId가 있다면 상태를 조회하거나 콜백을 기다리세요. 재발송하지 마세요.
  • messageId를 받지 못했다면 콘솔 로그에서 시간대와 수신 번호로 해당 발송을 찾으세요. 재발송하지 마세요.
  • 클라이언트 측 시간 초과는 이미 제출된 메시지를 절대 되돌리지 않습니다.
